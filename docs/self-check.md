# Ответы на контрольные вопросы

## Практическая работа 1

1. DevOps уменьшает разрыв между разработкой и эксплуатацией через общую ответственность, автоматизацию и обратную связь.
2. CALMS: Culture — культура сотрудничества; Automation — автоматизация; Lean — устранение потерь и небольшие партии изменений; Measurement — измерение результатов; Sharing — обмен знаниями.
3. `git add` выбирает изменения для индекса, `git commit` сохраняет содержимое индекса в локальной истории.
4. SSH использует пару ключей. Сервер проверяет владение закрытым ключом, который не передаётся на GitHub. Закрытый ключ нужно защищать; публичный можно регистрировать на сервере.
5. `origin` — имя удалённого репозитория, `main` — имя отправляемой ветки. Эти имена являются соглашениями, а не специальными командами.
6. Из четырёх метрик, рассматриваемых в методичке: частота развёртываний и время от изменения до его развёртывания. Другие две — доля неудачных изменений и время восстановления сервиса.

## Практическая работа 2

1. Изменения напрямую в main обходят обсуждение и проверку и могут нарушить стабильность общей ветки. В учебной начальной настройке возможен первый прямой коммит; для дальнейших изменений используется PR.
2. GitHub Flow: ветка от main, изменения и коммиты, push, PR, ревью, исправления, проверка, слияние и удаление ветки.
3. Merge — операция объединения истории. Pull Request — процесс предложения и обсуждения изменений с проверками; он может завершиться merge, squash merge или rebase merge.
4. Code Review — проверка изменений другим участником. Помогает находить ошибки, улучшать понятность решения и распространять знания.
5. Git распределённый: клон содержит историю. SVN централизованный: новая ревизия фиксируется на сервере.
6. `feat:` обозначает новую возможность в соглашении Conventional Commits.
7. Первый push новой ветки: `git push -u origin feature/hobby-project`.
8. CLI нужен для серверов без графического интерфейса, автоматизации и точного воспроизведения сложных операций.

## Merge или rebase

Merge подходит для объединения опубликованных веток: сохраняет существующие коммиты и показывает объединение истории. Например, вливание командной feature-ветки в main.

Rebase переносит изменения на новую базу и создаёт новые коммиты. Он удобен для приведения неопубликованной личной ветки к свежему main и объединения черновых коммитов. Историю общей ветки без согласования переписывать нельзя.
