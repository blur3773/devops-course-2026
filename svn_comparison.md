# Сравнение Git и SVN

## 1 Почему ветка в Git дешевая и насколько это верно для SVN

В Git ветка — перемещаемая ссылка на коммит. Для её создания не требуется копировать все файлы. В SVN ветки обычно организованы как копии каталогов, но сервер тоже поддерживает дешёвое копирование (cheap copies): утверждение, что SVN всегда физически копирует весь каталог и потому медленно создаёт ветку, неточно. Главное практическое отличие — в Git полная история и операции ветвления доступны локально; для серверных операций SVN требуется доступ к центральному репозиторию.

## 2 Можно ли сделать коммит в SVN без интернета

Без доступа к серверу репозитория — нельзя: коммит должен создать новую ревизию в центральном репозитории. При этом интернет не обязателен, если сервер доступен по локальной сети или используется локальный репозиторий file://. Изменять рабочие файлы и сравнивать их с базовой версией можно офлайн.

## 3 Когда SVN может быть предпочтительнее

В существующей инфраструктуре с процессами, завязанными на SVN; при необходимости централизованных прав доступа к отдельным каталогам; в рабочих процессах с блокировкой непригодных для слияния бинарных файлов. Выбор зависит от требований команды и стоимости миграции. Современный SVN поддерживает отслеживание слияний, поэтому считать любое слияние исключительно ручным некорректно.
